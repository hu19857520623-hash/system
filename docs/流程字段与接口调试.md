# 流程字段与接口调试

入口：ERP → 同步日志 → **流程字段与接口调试**（仅系统管理员）。直接路径 `/flow-debug`。

## 字段总表

目录由 `scripts/generate-flow-catalog.py` 从 ERP、OMS Prisma schema 及控制器路由声明生成。

显示系统、业务功能、模型、数据库表、代码字段、数据库列、类型、可空性、源码注释与行号。
支持搜索、功能筛选、导出 CSV；字段详情显示声明的外键关系及同功能接口。
同功能接口不意味着每个接口都会返回该字段。源码未声明的 JSON 内部字段、接口派生字段及 `any` 入参须结合接口源码和实际响应核对。

## 实时调试视图

接口：`GET /api/flow-debug/trace?orderNo=...`；SKU 查询使用 `customerCode=TKL005&sku=713105`。
目录接口：`GET /api/flow-debug/catalog`。

精确单号 / 内部 SKU → 明细、schema 外键及已登记的业务 ID 关联 → 商品、库存、费用、日志等相关记录。
字段详情会区分 schema 声明关系与业务 ID 约定，后者不是数据库外键。
数据库查询只使用 SELECT。ERP 与 OMS 单独展示，库存不相加。按 SKU 查询必须提供客户代码。
这些是数据库当前值，不会调用可能写入数据的业务详情接口，也不是接口请求的抓包记录。

默认每表最多 20 条、最多展开 4 层关联；长文本、嵌套数组可能截断，返回会标记表级截断。
不同查询期间业务仍可能更新；捕获时间为查询结束时间，结果不保证跨表事务一致。
缺失数据库表或列会明确显示迁移差异。未声明外键或单号关联的记录可能无法自动找到，不能把未查到理解为不存在。
仅对照相关数据，不能把关联记录视为已完成业务流转。

## 更新目录

仓库根目录运行 `python scripts/generate-flow-catalog.py`，再构建 ERP 后端。
产物：`erp/backend/src/modules/flow-debug/catalog.generated.json`。
修改 schema 或路由后应重新生成。schema 关系是系统内关系，跨系统通过同单号查询，不把 ERP 数字 ID 当成 OMS 字符串 ID。

关键流程映射包括商品身份、预约入库、收货清点、上架库存、出库计费和退件；页面“流转映射”列出主要字段和关联规则。
没有新增重复维护的业务总表，也无需执行数据库迁移。
