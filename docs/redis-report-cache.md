# OMS 第二批：客户隔离的报表汇总缓存

入口为 `GET /api/reports/summary`。登录状态仍由原 API 中间件从数据库刷新，随后验证 `report:read` 权限并确定客户范围，再访问 Redis。

非管理员必须有 customerId 和 customerCode，缺少任一绑定会返回 403，不能回退为全局查询。管理员全量汇总、不同客户、不同费用客户编码和不同角色使用不同键。键包含统计月份并经 SHA-256 处理：`takealot:cache:v1:oms:reports:summary:<hash>`。

缓存的内容只有库存周转、出库完成率、订单总数、库存展示合计、费用汇总、六个月趋势及费用构成，不缓存原始订单/库存/费用明细。TTL 为 30–35 秒，缓存组为 `oms-reports`。Redis 故障保留原数据库查询，数据库错误仍返回原错误处理。

OMS 成功的业务写响应完成后触发整个报表缓存组失效；失败响应、读取、登录与系统消息标记不触发失效。失效异步执行，缓存属于允许短暂延迟的展示数据。直接 SQL、外部脚本等不经过 OMS 请求的写入由 TTL 兜底。报表不是库存分配、余额扣减或结算的判断依据。

响应新增 `updatedAt`（汇总生成时间）和 `cacheMaxAgeSeconds`（35）。页面以北京时间显示更新时间和最大统计延迟，提供“刷新报表”。刷新读取当前有效缓存；过期或失效后重新汇总。

本次部署同时恢复首批缓存所需的源码、Redis 依赖和 Compose 转发。后续从 GitHub 同步源码的发布必须包含这些改动，否则会覆盖服务器上的接入。
