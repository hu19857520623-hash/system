# 货盘四档价格与负申购

## 操作入口

- ERP → 货盘库存 → 四档价格：维护 A/B/C/D。A 沿用基础价；B/C/D 可留空，缺价客户不能下单。
- ERP → 客户管理 → 价格档位：绑定客户价格。存量客户默认 A；客户换档不改历史成交价。
- OMS → 货盘选品 → 订单管理 → 退回清账 / 负申购：选原单、输入正数退回数量和原因，生成负数量、负金额。
- ERP → 货盘库存 → 负申购审核：财务或管理员通过、驳回。客户可在审核前撤销。

## 账务与库存

原申购单必须是已确认且扣款依据完整的 ERP 订单。可退数量扣除历史退款与待审核申请，同时校验当前客户持有量。审核时再次检查原单和当前持有量。

审核通过复用货盘收回退款事务：扣减客户持有与货盘已售，按原成交单价增加客户余额，写退款回执及同步记录，最后更新审核状态，整体原子提交。原始购买记录保留。已出库商品须先通过已有退货入库流程恢复持有，再申请退回；本功能不增加实物仓库存。

本次退款至客户余额，不直接执行银行付款。已有实际付款单的对账沿用原账务流程。

重复提交使用原 requestId；网络异常在会话存储中保留原请求，重开页面可继续核对。重复审核与撤销幂等。驳回、撤销释放退回额度。客户身份由 OMS 登录信息提供，不接受浏览器传入的客户代码覆盖。

客户负申购历史显示最近200条；后台显示最近200条待审核记录。已通过的退款可在原货盘退款记录中继续核对。价格绑定当前提供单客户操作，负申购每次关联一条原申购记录。

## 部署与验证

同时更新 ERP 后端、ERP 前端、OMS API、OMS 前端。数据库需已执行仓库现有迁移 `migrate_catalog_price_tiers.sql`（已在 migration-plan 注册）；遵循仓库既有迁移流程，不使用 prisma db push。负申购复用 operation_log，不新增表。

建议在测试环境用两档客户验证报价隔离；申购10件后退2件，审核前余额不变，通过后持有剩8件、余额增加原单2件金额；重复审核不再增加余额。并验证超退、撤销、驳回、网络错误重试、已出库持有不足等场景。
