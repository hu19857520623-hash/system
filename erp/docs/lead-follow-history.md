# 跟进记录编辑与访问范围

“最近一次跟进方式”读取最新一条跟进记录（ID倒序），与详情相同。空值显示“未填写”，原有微信记录保留为 `wechat`，企微使用独立值 `wecom`。无批量历史数据更新，无企微通讯录或聊天记录同步。

## 历史记录编辑

- 当前归属运营（`assigneeId`）或当前跟进销售拥有 `leads_follow.edit` 时，可修改该线索全部跟进记录，无须是原填写人。
- 管理员，以及同时拥有 `leads_pool.view_all`、`leads_follow.edit` 的账号，沿用全量访问权限。
- 原登记人、原填写人失去当前负责关系后，不能据此修改历史跟进记录。
- 可修改跟进方式、内容、下一步计划、下次跟进时间。原线索编号、填写人、填写时间不变；编辑旧记录不会将其变为最新记录。
- 入口：“待跟进/我的线索 → 跟进记录 → 编辑”，或“线索池 → 详情 → 跟进记录 → 编辑”。
- 保存后重新加载列表和详情。版本冲突返回409，保留未保存输入，用户刷新后重新编辑。
- 事务内复查当前归属、校验记录所属线索，并将修改前后值写入操作日志（`module=leads`，`action=update_follow_up`）。更新和日志写入处于同一事务。

## 记录级访问

- 所有带线索ID的控制器路由都经过 `LeadsRecordGuard`，覆盖详情、跟进、修改、二维码、成交附件等入口；全局登录和功能权限校验仍然生效。
- 列表和导出在业务筛选外追加访问范围，客户端指定归属、状态或ID不能突破该范围。
- 普通账号可读取本人归属、本人的当前跟进销售线索，以及本人登记的线索。登记人更正登记资料仍须满足原有“本人登记且未成交”规则。
- 公共池沿用原页面的可领取状态：新线索、已流失、暂无意向、再次跟进，以及未指定销售的跟进中线索；有线索池查看权限者可查看、领取。公共池不属于私人线索隔离范围，也不直接授予历史编辑权限。
- 跟进销售按完整姓名、账号、明确的多人名单匹配。子串相似不能授权；重名时需要明确账号。账号和姓名从服务端用户表获取，不使用客户端传入的身份。
- 现有跟进销售字段仍是历史文本；未能明确识别的姓名不授予访问权，管理员可核对并明确负责人。
