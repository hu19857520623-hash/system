# OMS 客户信用额度

ERP 客户管理 → 信用额度：有 `budget_credit.create` 权限的人员设置总额度并填写调整原因，系统在同一事务中保存审计。现有客户默认额度为 0。OMS 不能调整额度。

- 发货预扣、发运补扣、货盘购买、账单未付费用共用客户额度。
- 可用金额 = ERP 余额 + 信用总额度；负余额表示已用信用/欠款。
- 例如额度 1000、余额 100，消费 300 后余额为 -200，已用信用 200，可用 800；充值 250 后余额为 50，信用恢复至 1000，可用 1050。
- 额度不是充值，不增加累计充值，也不新增财务收入。退款和出库撤销仍按原单退回余额，自然恢复信用。
- 调低额度不能低于当前欠款；页面保存携带原额度，拒绝过期页面覆盖。消费、还款和调额都锁定同一客户行。
- 原采购、发运、充值的幂等规则继续生效；账单预览版本包含额度，调额后须重新预览。

## 部署

先在 ERP 后端执行 `npm run migrate:all`，应用新增的 `migrate_customer_credit_limit.sql`，再执行 `npm run prisma:generate` 并构建、部署 ERP 和 OMS。迁移仅添加默认 0 的 `customer.credit_limit`，不修改历史余额、充值、订单或已付凭据。不要重跑旧的删除信用额度迁移，不使用 `db push`。

本次开发未连接或修改生产数据库。
