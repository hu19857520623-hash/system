Takealot ERP 功能详细介绍

版本：V1.0 · 最后更新：2026-07-31

适用对象：产品、运营、仓储、财务、开发人员

系统架构：Vue 3 前端 + NestJS 后端 + MySQL 8.0

文档说明

本文档对 Takealot ERP 当前已实现功能 做逐项说明，包括：业务目的、适用角色、页面入口、核心操作、状态流转及与其他模块的衔接。未实现或部分实现的功能在相应章节末尾标注。

状态图例： ✅ 已实现 · 🟡 部分实现

一、系统基础

1.1 登录与鉴权

目的： 保障系统访问安全，按角色分配功能权限。

入口： /login

功能说明：

- 用户名 + 密码登录，成功后颁发 JWT Token，会话内访问所有 API。

- 登录后加载用户资料、角色名称、权限码列表（如 outbound.view、inbound.putaway）。

- 前端根据权限码控制菜单可见性与按钮启用状态；后端 @RequirePerms 二次校验，防止越权。

相关 API：

- POST /api/auth/login — 登录

- GET /api/auth/profile — 获取当前用户与权限

- PUT /api/auth/profile — 更新姓名、手机、邮箱

- PUT /api/auth/password — 修改密码

1.2 用户管理

目的： 维护 ERP 操作账号、角色与细粒度权限。

入口： /permissions（侧边栏「用户管理」）

功能说明：

- 创建/编辑/停用系统用户，绑定角色（系统管理员、采购、仓储、财务、销售等）。

- 支持用户级权限覆盖（在角色权限基础上增减）。

- 用户状态：启用（status=1）/ 停用。

1.3 工作台

目的： 登录后的运营指挥中心，一眼掌握待办与关键指标。

入口： /dashboard

功能说明：

区域内容
KPI 卡片可用库存 SKU 数、供应商数、线索数、待审采购单、待审选品、同步失败数等
业务流水线国内链（采购→中转→发运）与海外仓链（到仓→收货→上架→出库）各阶段待办计数
7 日趋势物流收货量折线图
待办通知可点击跳转：线索跟进、选品审核、采购审核、入库各阶段、出库、定价、同步失败
快捷入口一键进入常用页面
系统公告发布/编辑/删除公告，支持 ERP 与 OMS 渠道

相关 API： GET /api/dashboard/stats、/trends、/notifications、/announcements

1.4 操作日志

目的： 追溯关键业务操作（谁、何时、对什么对象做了什么）。

入口： /operation-logs

记录范围示例： 入库测量、上架、出库发运、定价确认、权限变更等。

字段： 操作人、模块、动作、目标类型/ID、详情 JSON、IP、时间。

1.5 异步导出导入

目的： 大批量 Excel/CSV 导入导出不阻塞浏览器，后台任务队列处理。

入口： /async-io

适用场景： 线索批量导入、库存导出、大列表导出等耗时操作。

二、获客与销售（CRM）

2.1 线索池

目的： 集中管理销售线索（公海），支持分配与领取。

入口： /leads/pool

核心操作：

- 新建线索： 公司名称、联系人、电话、邮箱、来源、备注。

- CSV 导入： 批量导入线索。

- 开始跟进： 将线索分配给销售并进入「跟进中」状态。

- 筛选： 状态（新线索/跟进中/已成交/已流失）、关键词搜索。

状态流转： new → following → deal / lost

2.2 我的跟进

目的： 销售个人待跟进线索的工作台。

入口： /leads/follow

核心操作：

- 写跟进： 跟进方式（电话等）、内容、下次计划、下次跟进时间；保存后线索保持 following。

- 标记成交： 填写店铺类型等信息，线索变为 deal，进入成交管理。

2.3 成交管理

目的： 管理已成交客户，并转化为 ERP 正式客户。

入口： /leads/deals

核心操作：

- 查看成交详情、跟进历史。

- 转 ERP 客户： 在系统中创建 Customer 记录，后续可走充值、结算、出库关联。

- 按渠道、店铺类型、负责人、成交日期筛选；支持导出。

2.4 获客报表

目的： 销售管理层查看转化数据（只读看板）。

入口： /leads/reports

展示内容： 线索总数、跟进数、成交数、流失数、转化率；渠道分布、月度趋势、销售排行、转化漏斗。

三、商品与选品

3.1 商品主数据

目的： 维护 SKU 级商品档案，作为采购、入库、库存、出库的统一主数据。

入口： /products

核心字段：

- 基础：SKU、SPU、品名、规格、品类、品牌、条码。

- 物理：长/宽/高（cm）、重量（kg）—— 入库测量会回写此处。

- 商业：成本、海运分摊、国内费用、Takealot 链接、图片。

- 关联：开发人、采购员、供应商。

核心操作： 新增/编辑、启用/停用、确认主数据、打印 SKU 标签、图片管理。

状态： active（可用）、pending（待完善）、inactive（停用）

3.2 产品开发（选品）

目的： 产品开发人员提交选品申请，填写多平台参考链接与预估成本。

入口： /product-dev

核心操作：

- 创建选品单：Takealot/Amazon/1688 链接、规格、预估成本、市场价、卖点说明。

- 提交审核 → 产品主管在「产品审核」页审批。

状态流转： draft → submitted → approved / rejected

3.3 产品审核

目的： 产品主管审核选品申请，通过后进入预采购流程。

入口： /product-audit

核心操作： 查看选品详情、通过/驳回（含审核意见）。

通过后： 生成预采购单或进入待分配采购员队列。

四、国内供应链

4.1 供应商管理

目的： 维护国内供应商档案（名称、联系人、结算方式等）。

入口： /suppliers

4.2 采购订单

目的： 国内采购全流程：预采购 → 正式 PO → 双审 → 核定数量 → 进入物流收货。

入口： /purchase

Tab 与流程：

Tab说明
预采购分配选品通过后，主管将预采购单分配给采购员
预采购单采购员维护供应商、仓库、SKU 数量与单价
采购订单正式 PO 列表
核定实际数量产品主管核定实际采购量
采购审核采购主管审核 PO
财务审核财务审核通过后同步商品主数据、货盘定价、成本台账

创建 PO 字段： 供应商、目标中转仓、预计到货、国内运费、SKU 明细（数量、单价）。

PO 状态： pending_actual_qty → pending_po_audit → pending_finance → finance_approved / rejected

财务审核通过后： 自动创建/更新 Product、ProductPricing（状态 waiting_freight）、写入成本台账。

4.3 物流中转仓

目的： 国内物流中转仓收货作业，对接采购 PO。

入口： /logistics-wh

核心操作：

- 按 PO 收货登记，更新中转仓在途/在库状态。

- 与「发运海外仓」衔接：货物从中转仓发往南非海外仓。

4.4 中转仓库存查询

目的： 查询国内中转仓当前库存（尚未发运海外仓的部分）。

入口： /logistics-inventory

4.5 发运海外仓

目的： 从国内中转仓创建入库预报，发运至南非海外仓（JHB 等）。

入口： /inbound/create

核心操作：

1. 填写基本信息

- 始发中转仓、目的海外仓、入仓号（必填）、预计到货、备注、附件。

2. 维护 SKU 明细

- SKU、入库数量、长宽高重量；支持 CSV 导入。

- 可选填写海运费（LCL/FCL），系统按体积分摊到 SKU。

3. 外箱装箱（可选）

- 配置箱码与箱内 SKU 数量，须与明细总数一致；也可提交后自动生成。

4. 草稿

- 支持保存草稿、继续编辑、正式提交。

5. 提交后

- 创建 InboundOrder，状态 pending_receipt（在途）。

- 海运费同步至对应 SKU 的货盘定价记录。

标签： 可下载 SKU 标签、外箱标 HTML/PDF，供国内贴标。

五、海外仓 · 仓储作业

5.1 库位管理

目的： 维护海外仓库区与货架库位，供上架、拣货使用。

入口： /warehouse/locations

层级结构：

- 仓库（warehouseType=wms，如 WMS-JHB-01）

- 库区（WarehouseZone，分区字母 A/B/C…）

- 库位（WarehouseLocation，如 A-01-02，状态 available）

核心操作： 批量创建库位、打印库位标签、查看库位当前库存。

5.2 到仓扫描（核心作业台）

目的： 海外仓现场一站式完成入库后半段：到仓确认 → 收货 → 清点 → 测量 → 上架。

入口： /inbound/arrival-scan

（旧「入库上架」路由已合并至此，?step=putaway 可直达上架步骤）

适用角色： 海外仓收货员、上架员。

五步流程：

#### 步骤 1：到仓确认

- 选择操作仓库（海外仓）。

- 扫描或输入：入库单号 / 入仓号 / 跟踪号。

- 确认到仓 → 状态 pending_receipt → arrived。

#### 步骤 2：扫箱收货

- 有外箱标： 扫描箱码，整箱计入收货。

- 无外箱标： 扫描 SKU + 填写每箱件数，逐件累加。

- 支持「开始收货」后持续扫箱 → 状态 receiving。

#### 步骤 3：人工清点（QC）

- 按 SKU 确认实收数量。

- QC 状态：通过 / 异常；可填 QC 备注。

- 清点完成 → pending_putaway；若有差异且不接受 → exception。

#### 步骤 4：测量体积

- 逐 SKU 填写实测长、宽、高（cm）。

- 写入 Product.lengthCm/widthCm/heightCm。

- 必须先测量，才能进入上架步骤。

#### 步骤 5：扫码上架

- 扫描 SKU + 目标库位 + 上架数量。

- 写入 InboundPutawayItem、InventoryLocation，增加 Inventory.availableQty。

- 全部上架完成 → 入库单 completed。

- 触发货盘定价 inboundQty 更新，满足条件时可自动 OMS 可下单。

异常处理： 状态为 exception 的单据需主管「放行上架」后继续测量/上架。

相关 API：

- POST /api/inbound/arrival-scan

- POST /api/inbound/:id/receive-box

- POST /api/inbound/:id/qc

- POST /api/inbound/:id/measure-dimensions

- POST /api/inbound/:id/putaway

- POST /api/inbound/:id/resolve-exception

5.3 入库单管理

目的： 后台查询与管理入库单，跟踪全状态；部分操作可在此发起，实际上架仍在「到仓扫描」。

入口： /inbound/receipt

状态 Tab：

状态含义
在途已发运，未到海外仓
已到仓已确认到仓，待收货
收货中正在扫箱收货
待上架清点完成，待测量/上架
已入库上架完成
异常清点或流程异常

核心操作： 搜索、查看详情、开始收货、提交清点（QC 弹窗）、异常放行、跳转到仓扫描。

5.4 库存查询

目的： 查询海外仓已上架实收库存，支持库位级明细与手工调整。

入口： /inventory

筛选条件：

- 客户代码、SKU（支持空格分隔多个）、仓库（多选，默认 JHB）。

- 产品代码 / 品名（可精确匹配）、EAN 条码。

- 数量类型（可用/总量/锁定）及区间。

- 品类关键词、低库存预警。

列表展示： SKU、品名、可用/总量/锁定、在途数量、平均成本等。

核心操作：

- 点击 SKU → 查看库位分布（各库位数量）。

- 查看出库记录（该 SKU 历史出库）。

- 库存导入 / 库位调整（需 inventory.adjust 权限）：手工增加或修正库位库存。

- 导出 CSV。

库存模型：

- Inventory：仓库维度汇总（totalQty / availableQty / lockedQty）。

- InventoryLocation：库位 + SKU 维度明细。

- 出库创建时：availableQty ↓，lockedQty ↑；发运或取消时相应释放/扣减。

5.5 SKU 查询

目的： 以单个 SKU 为视角，聚合展示主数据、各仓库存、近期变动。

入口： /inventory/sku-query（可从库存查询页跳转）

5.6 出库单管理

目的： 管理出库全生命周期：创建 → 拣货 → 复核 → 换标 → 发运 → 送达。

入口： /outbound

列表布局（对标 WMS）：

- 顶部 4 列筛选网格：单号、客户、时间、SKU、仓库、目的地、物流、承运商、拣货员、换标、批次、平台、预约、问题件等；点「查询」生效。

- 状态 Tab（带数量）：待拣货 / 复核中 / 待换标 / 待发运 / 已发货 / 已送达 / 异常 / 已作废 / 问题件 / 全部。

- 工具栏： 预约派送、分配拣货员、打印拣货单、导出、+ 预约发货。

- 表格： NO.、FBA 编号、出库单号（可复制）、发货仓库、物流产品、承运商、箱货类型、状态；行内「操作」下拉。

状态与操作对照：

状态可用操作
待拣货分配拣货员、下载/打印拣货单、完成拣货
复核中复核打包（可填打托信息）
待换标扫码换标（扫旧条码确认）
待发运发运（填跟踪号、承运商）
已发运确认送达（可选 POD 码）
异常解除异常（恢复原状态）
任意（未完结）标记异常、取消（FBA 可预约派送）

完整流程：

创建出库单（锁定库存）
    ↓
待拣货 → 分配拣货员 → 完成拣货（选库位、拣货来源 PDA/拣货单）
    ↓
复核中 → 复核打包（复核人、是否打托）
    ↓
[若需换标] 待换标 → 扫码换标确认
    ↓
待发运 → 发运（扣减 totalQty/lockedQty，写 billing_charge）
    ↓
已发运 → 确认送达（POD）
    ↓
已送达

筛选与导出：

- 支持 CSV 导出（含客户、SKU 摘要、拣货员、复核、打托、跟踪号等 20+ 字段）。

- GET /api/outbound/status-counts 返回各 Tab 数量。

计费联动： 发运时按件数自动生成拣货费、打包费、出库运费等 BillingCharge。

5.7 预约发货（创建出库单）

目的： 独立全页创建出库单，面向 Takealot 入仓等场景，表单比列表页弹窗更完整。

入口： /outbound/create

出库信息：

- 发货仓库、出库类型（Takealot / FBA / CPT 自提 / 本地配送）。

- 配送方式、参考号、平台、PO 单号。

- Takealot 目的仓（JHB1 / CPT1 / DBN1 → 写入物流产品字段）。

- 客户、是否换标、备注。

Takealot 文件上传（前端四类）：

- 外箱标、SKU 标签、发货清单、预约单。

- 🟡 当前后端仅保存第一个附件；多附件子表待扩展。

货品明细：

- 从该仓库可用库存中选择 SKU。

- 填写出库数量、申报品名、申报价值、行备注。

- 提交时校验数量 ≤ 可用库存。

提交结果： 创建 OutboundOrder（状态 pending_pick），锁定库存，跳转出库单管理。

六、货盘与 OMS

6.1 货盘库存（定价中心）

目的： 运营对「已发运/已入库 SKU」进行成本核算、定价，并同步至 OMS 供客户下单。

入口： /pricing

定价状态 Tab：

状态含义
待发运PO 财务审核后创建，等待国内发运
待定价海运费已回传，等待运营填价
已定价待同步售价已确认，待推 OMS
已同步 OMS已在 OMS 展示/可下单

定价表单字段：

- 成本、海运费、国内费、汇率。

- 市场参考价、目标利润率、最终售价、定价逻辑说明。

- 平台佣金、平台配送费、海外配送费。

- 可见库存（OMS 展示用）。

核心操作：

- 海运费回传： 发运海外仓或手工回调写入 seaFreight。

- 确认定价： 填写最终售价 → priced。

- 同步 OMS： 设置 visibleOnOms / orderableOnOms → synced。

- 调价（reprice）： 已同步 SKU 改价后再次同步。

入库联动： 海外仓上架完成后更新 inboundQty，满足规则时可自动变为 OMS 可下单。

6.2 OMS 对外接口

目的： 供 OMS 系统拉取货盘、客户下单，与 ERP 库存/余额联动。

API说明
GET /api/pricing/oms/catalogOMS 拉取可售 SKU 目录
GET /api/pricing/oms/catalog/:sku单 SKU 详情
POST /api/pricing/oms/purchaseOMS 下单回调：扣客户余额、写 OmsCatalogOrder、记 catalog_purchase 费用

6.3 客户 SKU 库存

目的： 记录客户通过 OMS 购买的 SKU 持有量（货盘库存的客户视图）。

数据表： customer_sku_inventory（customerId + sku + quantity + unitPrice）

入口： 客户详情 / 货盘相关页面可查看。

七、财务

7.1 客户列表

目的： 管理 ERP 正式客户（由成交转化或手工创建）。

入口： /customers

核心字段： 客户编码、名称、联系人、余额、状态。

核心操作： 新建/编辑客户、查看 SKU 持有、充值历史。

7.2 客户充值

目的： 为客户账户充值，供 OMS 下单扣款。

入口： /customer-recharge

操作： 选择客户、充值金额、支付方式、备注 → 立即到账（Customer.balance ↑），写入 CustomerRecharge。

7.3 客户结算

目的： 汇总 WMS/ERP 产生的各类费用，按客户生成账单并确认入账。

入口： /billing

两个视图：

#### 费用明细

- 逐笔费用：出库拣货、打包、发运、换标、仓储、OMS 购货等。

- 筛选：客户、来源（WMS/手工）、费用类型、日期。

- 手工作业费录入：换标、换箱、检验等。

#### 客户维度（账单）

- 选定时间范围内「待入账」费用 → 生成账单（按客户汇总为 BillingOrder）。

- 确认账单 → 费用状态变为已入账。

费用来源：

- 自动：出库发运时写 BillingCharge（source=wms）。

- OMS 下单：写 catalog_purchase 类型费用。

- 手工：财务录入换标等工费。

chargeType 示例： wms_outbound、picking、outbound_ship、relabel、catalog_purchase、storage、handling 等。

7.4 供应商海运账单

数据来源： 采购财务审核、发运分摊、入库确认等环节写入。

九、端到端主业务链路

┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  线索/成交   │ →  │  选品/审核   │ →  │  预采购/PO  │
└─────────────┘    └─────────────┘    └──────┬──────┘
                                              ↓
┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  OMS 客户下单 │ ←  │  货盘定价    │ ←  │ 中转仓/发运  │
└──────┬──────┘    └─────────────┘    └──────┬──────┘
       ↓                                      ↓
┌─────────────┐                      ┌─────────────┐
│  客户结算    │ ← ─ ─ ─ ─ ─ ─ ─ ─ │  到仓/上架   │
└─────────────┘                      └──────┬──────┘
       ↑                                      ↓
       └──────── 出库/计费 ← ─ ─ ─ ─  库存查询  ─┘

典型 Takealot 路径：

1. 选品 → 采购 → 中转仓收货 → 发运 JHB 海外仓

2. 到仓扫描（收货→清点→测量→上架）→ 货盘定价 → 同步 OMS

3. 客户 OMS 下单 / 或直接预约发货（Takealot 入仓）

4. 出库（拣货→复核→发运→送达）→ 自动计费 → 客户结算
